# Tema Label

Premium fashion storefront + admin dashboard.
**Stack:** Next.js 16 (App Router) · React 19 · Tailwind 4 · Supabase (Auth + Postgres) · Prisma 7 · Zustand.

## Getting started

```bash
npm install
cp .env.example .env.local      # fill in the Supabase values
npm run db:migrate              # apply migrations (uses DIRECT_URL)
npm run db:seed                 # optional: demo catalog
cp admins.example.json admins.local.json   # edit emails / passwords
npm run db:seed:admins          # creates admin accounts in Supabase Auth
npm run dev
```

Storefront: `http://localhost:3000` · Admin: `http://localhost:3000/admin`

## Architecture

- `app/` — storefront routes, `app/admin/` — admin panel (guarded by `proxy.ts` + `requireAdmin()` on every page and action).
- `lib/catalog` — cached read layer (`unstable_cache`, tag `catalog`). Admin writes call `updateTag("catalog")`, so edits go live immediately.
- `app/checkout/actions.ts` — order placement: validates input, re-prices from the DB, reserves stock atomically in a transaction, rate-limited.
- `prisma/schema.prisma` — data model. All tables have **Row Level Security enabled with no policies**: the Supabase REST API cannot read or write them; only the server (Prisma) can.
- Roles: `SUPER_ADMIN`, `ADMIN`, `EDITOR`, `SUPPORT` (`lib/auth/permissions.ts`). Every admin write is recorded in the activity log.

## Deploying

1. Set every variable from `.env.example` in your host (`NEXT_PUBLIC_SITE_URL` = your domain).
2. Run `npm run db:migrate` against production before the first deploy.
3. `npm run build && npm start` (or Vercel).

## Look & feel

- **Light / dark mode** across the whole site (storefront + admin). It follows the visitor's OS until they pick one with the toggle in the header; the choice is saved and applied before first paint (no flash). Logic lives in `lib/theme.ts`; colours are CSS variables in `app/globals.css` (`.dark` block).
- **Mini bag** (slide-over) opens whenever something is added; quick-add sizes on product cards (desktop hover).
- Placeholder product photos are generated by `node scripts/generate-placeholder-images.mjs`. Replace them with real photography from *Admin → Products*.

## Testing

`npm run qa:all` runs types, lint, unit tests, the real-database checkout integration tests and the database integrity checks.
With a running build, `npm run qa:roles` and `npm run qa:a11y` check the admin permission matrix and page accessibility.
Details and the latest results are in [TEST-REPORT.md](TEST-REPORT.md).

## Operations

- **Health check:** `GET /api/health` → `200 {"status":"ok"}` when the database answers, `503` otherwise. Point your uptime monitor at it.
- **Security headers + CSP** are set in `next.config.ts` (CSP only in production). `/admin` and `/api` are disallowed in `robots.txt` and sent with `noindex`.
- **Forms** (contact, newsletter, order tracking, checkout) validate with Zod on the server, have a honeypot field and are rate-limited.
- **CI:** `.github/workflows/ci.yml` runs typecheck, lint, tests and a production dependency audit on every push/PR. (`next build` needs database access, so run it in your deploy pipeline.)
- **Content to configure before launch:** social links in `constants/site.ts`, support email/phone and shipping fees in *Admin → Settings*, real product photos via *Admin → Products*.

## Known limitations / next steps

- Payment: Cash on Delivery, **InstaPay** and **mobile wallets** (Vodafone Cash etc.) via manual transfer verification: set the IPA / wallet number in *Admin → Settings*, customers send the money and enter the reference (optionally upload a screenshot, stored in a private bucket), you confirm each one from the order page. Automatic card/wallet capture needs a gateway (e.g. Paymob / Fawry / Stripe) wired into `placeOrder`.
- Rate limiting is in-memory (per instance). Use Redis/Upstash for multi-instance deployments.
- No customer accounts: checkout is guest-only; customers can follow an order at `/track` with the order number + email.
- No transactional emails (order confirmation, shipping updates) yet — add a provider such as Resend.
- No product reviews (the placeholder reviews were removed rather than showing fabricated ones).
- Seed product images are flat placeholders — replace them with real photography.
